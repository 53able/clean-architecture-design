### 手順

1. [ ] characterization testまたはユースケーステストを追加する。
2. [ ] handler/controllerから薄い入口を抽出する。
3. [ ] portを内側へ定義する。
4. [ ] adapterで外部形式を変換する。
5. [ ] composition rootへ具体実装とDIを集める。
6. [ ] 依存・循環・境界横断型を検査する。
7. [ ] テストと既存検証を実行する。

### 停止条件

次のいずれかが成立したら、分割を止めて設計診断へ戻る。

- 変更対象が減らず、無関係なモジュールまで広がる。
- 新しいportが外部SDK型または一実装のメソッドをそのまま再掲する。
- DTOがHTTP、ORM、DB行の型を写し替えるだけで、内側の語彙を持たない。
- ユースケースの期待結果を外部I/Oなしにテストできない。
- 独立開発、独立テスト、独立デプロイの便益を説明できない。
- 新しいserviceが共有DB、同期呼び出し、または同時デプロイを増やす。
